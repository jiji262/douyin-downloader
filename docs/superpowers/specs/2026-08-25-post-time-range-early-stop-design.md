# 博主主页按时间下载提前停页设计

## 背景

博主主页作品下载目前先完整拉取分页，再统一应用 `start_time` / `end_time`
过滤。一个拥有约 3000 个作品的主页，即使用户只选择最近几天且最终只有一个作品命中，
仍会请求约 150 页，翻页耗时可能达到数分钟。

本次只优化博主主页的“作品”模式（`post`）。喜欢、合集、音乐、收藏及收藏夹合集
没有可靠的全局发布时间顺序，继续保持现有完整收集后过滤的行为。

## 目标

1. 设置起始日期时，在确认分页已经越过时间下界后停止继续请求旧作品。
2. 除修正结束日期的既有契约偏差外，提前停页只减少请求，不改变完整遍历本应得到的作品集合。
3. 保持现有增量下载语义：时间范围决定检查范围，范围内是否下载仍由磁盘文件状态决定。
4. 不增加用户开关，不引入新的 YAML、HTTP API 或持久化字段。
5. Desktop 与 CLI 的共享 Python 实现和测试保持一致。

## 非目标

- 不优化 `like`、`mix`、`music`、`collect` 或 `collectmix`。
- 不保存或复用博主分页 cursor，不建立数据库增量检查点。
- 不使用 SQLite 下载历史或最新作品时间决定是否继续翻页。
- 不改变浏览器回补的滚动与作品详情补全策略。
- 不改变单条作品、合集链接、音乐链接和直播链接的下载行为。

## 用户体验

用户继续使用现有“按作品发布时间筛选”日期控件，无需理解或开启新的性能选项。

正常提前停止时，任务进度显示：

```text
已到达起始日期，提前结束翻页（检查 3 页，共 60 条）
```

若作品时间缺失或顺序异常，任务不报错、不要求用户选择，自动恢复完整遍历。日志只记录一次
降级原因，避免持续刷屏。

## 日期范围语义

日期继续按运行环境的本地时区解释。范围采用左闭右开区间：

```text
[起始日期 00:00:00, 结束日期次日 00:00:00)
```

- 起始日期当天的作品包含在内。
- 结束日期当天的作品全部包含在内。
- 只设置起始日期时，没有时间上界。
- 只设置结束日期时仍需从最新作品向后查找，不能提前停页。
- 未设置起始日期时，提前停页功能关闭。

现有后端把结束日期解析为当天 `00:00:00`，与 UI“结束日期含当日 23:59:59”的说明不一致。
本次在共享时间过滤逻辑中一并改为“次日零点前”，使 UI、CLI 和实际结果一致。

## 分页算法

### 基本原则

`post` 正常 API 分页通常按发布时间从新到旧返回，但该顺序不是仓库中的正式接口契约。
因此不能在遇到第一条旧作品时立即停止，而要先验证已观察到的顺序，并在越过边界后再请求
一页作为确认。

### 每页处理顺序

1. 请求并标准化当前页，保留现有空页、超时和 cursor 停滞检测。
2. 将当前页作品加入已收集列表；最终结果仍经过现有置顶、日期、媒体类型和数量过滤。
3. 用置顶策略、日期与媒体类型过滤后的候选作品数量判断 `number.post` 是否已满足。
4. 从当前页取出非置顶作品的有效 `create_time`，检查页内及跨页是否保持非递增顺序。
5. 记录是否已经观察到早于 `start_time` 的普通作品，并按下述确认规则决定是否继续。

置顶作品仍按现有设置决定是否下载，也仍受日期范围过滤，但永远不参与顺序验证和停页判断。

### 边界确认

- 第一次观察到普通作品早于 `start_time` 的页面称为“边界页”。边界页中的范围内作品必须
  正常保留，不能先停后筛。
- 如果边界页仍有下一页，再请求一页作为确认页。
- 确认页的所有非置顶作品都有有效时间、全部早于 `start_time`，且整体顺序继续保持非递增时，
  正常停止分页。
- 确认页没有非置顶作品时缺少足够的排序证据，关闭时间早停并继续完整遍历。
- 如果边界页已经是最后一页，则按 API 自然结束，无需额外确认。
- 如果确认页重新出现不早于 `start_time` 的作品，该任务视为跨页乱序，关闭时间早停并继续
  完整遍历。

该策略最多多请求一个确认页。若时间边界位于前两页，3000 个作品的主页通常只需检查
2 至 3 页，而不是约 150 页。

### 顺序与时间异常

以下任一情况都会关闭当前任务的时间早停，后续恢复现有完整分页：

- 用于判断的非置顶作品缺少有效 `create_time`；
- 同一页内出现发布时间回升；
- 当前页第一条普通作品比上一页最后一条普通作品更新；
- 确认页重新出现时间戳不早于 `start_time` 的作品。

关闭优化不会丢弃已经收集的作品，也不会改变最终过滤规则。

## 与现有筛选的组合

### 结束日期

比 `end_time` 更新的作品不下载，但仍需继续翻页，直到进入目标范围或越过 `start_time`。
结束日期本身不能成为停页条件。

### 数量上限

`number.post` 必须统计经过置顶、日期和媒体类型筛选后的候选作品。不能因为前几页存在大量
晚于结束日期的视频或不匹配的媒体类型，就按原始条数提前结束并返回不足数量的结果。

候选数量达到上限时，可以沿用现有数量上限提前停止，不必继续寻找时间边界。最终过滤仍
负责裁剪为准确数量。

### 增量下载

时间早停与增量下载相互独立：

- 时间分页只决定哪些作品进入当前任务的检查范围。
- `increment=true` 时，范围内存在有效主媒体的作品跳过，缺失、被删除或为空的文件重新下载。
- `increment=false` 时，范围内作品按现有支持模式进入覆盖下载。
- SQLite 只保留历史与元数据用途，不参与停页判断。

因此，用户想补齐很早以前删除的文件时，仍需把起始日期设置到那个作品所在日期或取消日期
下界；这与现有“日期决定补齐范围”的产品语义一致。

### 浏览器回补

因时间边界主动结束是正常结果，必须与“分页受限”区分，不能触发浏览器回补。

API 超时、cursor 停滞、疑似异常空页等现有受限场景仍走浏览器回补。首期不改浏览器滚动的
时间早停；一旦进入该兜底路径，以完整性优先，允许继续完整扫描。

## 代码边界

### `core/downloader_base.py`

- 集中解析起始时间与结束时间的独占上界，避免分页判断和最终过滤使用不同边界。
- `_filter_by_time()` 继续作为最终正确性保护，并修正结束日期只包含零点的问题。

### `core/user_modes/post_strategy.py`

- 在现有专用分页循环中维护页数、原始条数、最后一个普通作品时间、边界页和是否已降级。
- 计算经过当前过滤条件后的候选数量。
- 将“正常时间结束”与“分页受限”分开传回调用方，并更新一次用户可见进度。

### 测试与双仓同步

- 在 Desktop 和 CLI 的共享 Python 测试中覆盖相同场景。
- 共享文件修改完成后运行 Desktop 的 `scripts/sync-to-cli.sh --check`，或使用逐文件比较确认一致。
- 不修改 Desktop 日期控件及 HTTP 请求字段，因为现有 UI/API 已能传递所需日期。

## 错误处理与可观察性

- 时间早停降级记录 warning，包含模式、页码和原因，不记录 cookie、URL 查询参数或作品详情。
- 正常早停记录 info，并通过现有进度上报器显示页数和检查条数。
- 配置中没有有效起始日期时不创建早停状态，也不增加额外日志。
- 早停逻辑自身不得抛出下载失败；无法证明安全时一律完整遍历。

## 测试设计

1. **正常边界**：倒序分页包含较新页、混合边界页和全旧确认页；断言只请求到确认页，范围内
   作品完整且不触发浏览器回补。
2. **置顶与异常顺序**：旧置顶不触发边界；时间缺失、页内回升、跨页回插均关闭早停并请求
   到 API 自然结束。
3. **筛选组合**：比结束日期更新的作品不计入数量上限；媒体类型不匹配的作品不计数；满足
   过滤后数量上限时仍能正常提前结束。
4. **日期边界**：起始日零点包含、结束日任意时刻包含、结束日次日零点排除；只设置结束日期
   不启用时间早停。
5. **回归与共享语义**：未设置日期、非 `post` 模式、浏览器受限回补以及磁盘缺失文件补下载
   保持原行为；两仓相关测试、全量 pytest 与 ruff 均通过。

## 验收标准

- 对相同的有序模拟主页，优化结果与完整遍历后过滤的作品 ID 集合一致。
- 时间边界位于前两页的 3000 作品场景，请求数不超过边界页加一个确认页。
- 正常时间早停不会启动浏览器回补，也不会显示分页异常。
- 任一排序或时间异常场景均不漏作品，而是恢复完整遍历。
- 结束日期实际包含完整当天，与界面说明一致。
- Desktop 与 CLI 的共享实现保持一致，相关测试、全量测试和 lint 通过。

## 后续扩展条件

只有在获得真实接口证据并建立乱序回归样本后，才考虑把相同优化扩展到 `like`。二级展开的
`mix`、`music`、`collect` 和 `collectmix` 不复用本设计的全局时间早停。
